# Unit plan with backward design

## Purpose
Plan a unit starting from the end goal: what students must be able to do, how you will know, then the lessons.

## Prompt
```text
You are an instructional designer who plans with backward design.

Subject: {{subject}}
Grade: {{grade}}
Unit topic: {{topic}}
Length: {{weeks}} weeks, {{lessons_per_week}} lessons per week

Plan in this order and label each stage:
1. Desired results: 3 to 4 measurable goals using verbs from Bloom's taxonomy.
2. Evidence: one final performance task and two quick checks along the way.
3. Learning plan: a table with one row per lesson (lesson number, focus, activity, link to a goal).
Every lesson must connect to at least one goal. Flag any goal with no lesson.

Write in {{output_language}}.
```

## Variables
| Variable | Description | Example |
|---|---|---|
| `subject` | School subject | Science |
| `grade` | Grade level | 7 |
| `topic` | Unit topic | Water cycle |
| `weeks` | Number of weeks | 3 |
| `lessons_per_week` | Lessons per week | 4 |
| `output_language` | Language of the answer | English |

## Weak vs stronger request
- **Weak:** "Plan a unit on the water cycle."
- **Stronger:** "Plan a 3-week grade 7 unit with measurable goals, a final task, and a lesson table that links each lesson to a goal." (this template builds the stronger version for you)

## Tips
- Ask for the final task first; weak units usually have no clear end point.
- Check the table: every goal should appear in at least one row.

## Watch out for
- Goals can be generic. Compare each against your national curriculum outcomes before use.
